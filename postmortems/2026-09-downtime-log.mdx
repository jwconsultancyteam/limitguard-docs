## Planned maintenance, 2026-09-19

All times UTC.

| When | What |
|---|---|
| 2026-09-19 00:34 | Tracing backend upgraded. The API does not depend on it to serve requests and stayed up. |
| 2026-09-19 00:40:55 | Container engine upgrade on the API host starts. Every container on the host stops, including the API and the reverse proxy in front of it. |
| 2026-09-19 00:41:45 | All containers back and healthy. `api.limitguard.ai/health` returns 200. |

About 50 seconds of downtime. Requests in that window could not connect. Every service restarted from its existing data. The upgrade was run in the lowest-traffic hour.

**Candidate contributor, added 2026-09-23:** every deploy to `main` stops the running
API before the new one listens, producing an empty-body 503 for roughly 43–45 s
(measured in `infra/contabo/README.md`, "Deploy window (#430)"). 119 commits landed
on `main` in this window, but they do not line up with the daily totals: 2026-09-08
had the most (over 75) and only 3 minutes of API downtime, while 2026-09-13 had none
and 7 minutes. Deploys can explain part of some rows at most, not the pattern as a
whole — this has not been reconciled per-row yet.
